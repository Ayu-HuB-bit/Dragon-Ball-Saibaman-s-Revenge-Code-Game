Dragon Ball: Saibaman's Revenge - Systems Logic Validation & Behavioral Sandbox

## 📋 Project Overview
Dragon Ball: Saibaman's Revenge is an interactive, real-time physics and logic engine built entirely in native JavaScript. Rather than a standalone gameplay project, this repository serves as a functional software testing environment used to evaluate complex state machines, mathematical collision tracking, and real-time interaction feedback loops.

The primary objective was to build a stable code environment capable of processing simultaneous asset logic transitions while applying core cognitive psychology and human-computer interaction (HCI) frameworks.

---

## 🔬 Systems Engineering & Cognitive UX Frameworks Applied
The mechanical structure and visual rendering layers of this application directly validate critical human performance and script optimization parameters:

### 1. Attentional Allocation & Visual Salience Engineering
To prevent user cognitive fatigue during intense interactive sequences, the canvas asset layering was engineered using cognitive psychology models:
* **Top-Down (Goal-Directed) Attention Support:** Structured core interactive elements (player coordinates, active targets) with distinct, high-contrast assets so the user's brain can immediately locate and execute goal-directed movements.
* **Bottom-Up (Stimulus-Driven) Attentional Prompts:** Engineered high-salience system changes (damage states, flashing status alerts) to immediately pull the user's peripheral vision to critical data updates without triggering inattentional blindness.
* **Sensory Memory Processing Optimization:** Standardized asset velocities and rendering rates to match human sensory ingestion thresholds, preventing visual clutter from overwhelming active working memory boundaries.

### 2. Functional State Machine Validation & Crash Mitigation
The script development pipeline utilized rigorous manual quality assurance (QA) methods to verify system stability under heavy data loads:
* **Simultaneous Input Tracking & Boundary Constraints:** Ran targeted regression test sequences to identify edge-case logic crashes during rapid control saturation (e.g., executing an action trigger precisely on the frame of an active state change).
* **Multi-Variable Collision Telemetry:** Implemented absolute mathematical boundary tracking ($X/Y$ coordinate validation) to ensure real-time sprite intersections execute flawlessly without clipping, asset drops, or physics computation failures.
* **Runtime Error Isolation:** Isolated and logged performance dips to streamline logic calculation efficiency, ensuring steady frame execution loops across varying hardware constraints.

### 3. Flow State & Skill-Challenge Calibration
The application’s difficulty scaling loops were modeled directly against psychological behavioral design curves:
* **Anxiety vs. Boredom Equilibrium:** Engineered dynamic variable modifiers that scale task difficulty based on real-time success metrics, keeping the interaction securely balanced within the optimal "Flow State" to prevent mechanical stagnation or early user frustration.
