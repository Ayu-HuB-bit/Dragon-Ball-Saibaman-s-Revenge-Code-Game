Dragon Ball: Saibaman's Revenge - Systems Logic Validation & Behavioral Sandbox

 ## 📋 Project Overview
Dragon Ball: Saibaman's Revenge is an interactive, real-time logic and physics simulation built entirely in native JavaScript. Rather than functioning as a standalone gameplay project, this repository serves as a functional software testing environment used to evaluate complex state machines, mathematical collision tracking, and real-time interaction feedback loops under heavy data loads.

The primary engineering objective was to build a stable runtime environment capable of processing simultaneous asset logic transitions while applying core cognitive psychology and human-computer interaction (HCI) frameworks.

---

## 🔬 Systems Engineering & Cognitive UX Frameworks Applied
The mechanical structure and visual rendering layers of this application were designed and validated against strict human performance and script optimization parameters:

### 1. Attentional Allocation & Visual Salience Engineering
To minimize user cognitive fatigue during high-velocity interactive sequences, the canvas asset layering was engineered using cognitive psychology models:
* **Top-Down (Goal-Directed) Attention Support:** Structured core interactive elements, including player coordinates and active targets, with distinct, high-contrast assets so the user's brain can immediately locate and execute goal-directed movements.
* **Bottom-Up (Stimulus-Driven) Attentional Prompts:** Engineered high-salience system changes, such as damage states and status alerts, to immediately pull the user's peripheral vision to critical data updates without triggering inattentional blindness.
* **Sensory Memory Processing Optimization:** Standardized asset velocities and rendering rates to match human sensory ingestion thresholds, preventing visual clutter from overwhelming active working memory boundaries.

### 2. Functional State Machine Validation & Crash Mitigation
The script development pipeline utilized rigorous manual quality assurance (QA) methods to verify system stability under rapid user interaction:
* **Simultaneous Input Tracking & Boundary Constraints:** Ran targeted regression test sequences to identify edge-case logic conflicts during rapid control saturation, ensuring the system handles actions cleanly when an input occurs precisely on a state transition frame.
* **Multi-Variable Collision Telemetry:** Implemented absolute mathematical boundary tracking ($X/Y$ coordinate validation) to ensure real-time sprite intersections execute flawlessly without clipping, asset drops, or physics computation failures.
* **Runtime Error Isolation:** Isolated and logged performance dips to streamline logic calculation efficiency, ensuring steady frame execution loops across varying hardware constraints.

### 3. Challenge-Skill Calibration & Flow Theory
The application’s difficulty scaling loops were modeled directly against psychological behavioral design curves to maintain user engagement:
* **Anxiety vs. Boredom Equilibrium:** Engineered dynamic variable modifiers that scale task difficulty based on real-time success metrics, keeping the interaction securely balanced within the optimal "Flow State" to prevent mechanical stagnation or early user frustration.
